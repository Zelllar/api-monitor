# API Monitor

API Monitor — веб-приложение для мониторинга доступности HTTP- и HTTPS-адресов и отслеживания времени ответа серверов.

Приложение позволяет добавлять URL для мониторинга, настраивать интервалы проверок и отслеживать доступность сервисов через Dashboard с историей проверок и информацией о состоянии каждого монитора.

## Возможности

- **Мониторинг доступности** — автоматическая проверка зарегистрированных URL с заданным интервалом.
- **Ручная проверка** — возможность запустить проверку в любой момент.
- **Отслеживание статусов** — определение доступности адреса с использованием статусов `UP` и `DOWN`.
- **Измерение времени ответа** — сохранение времени выполнения HTTP-запросов.
- **История проверок** — хранение и отображение результатов предыдущих проверок.
- **HTTP-коды ответа** — сохранение кодов состояния HTTP.
- **Обработка ошибок** — сохранение сообщений об ошибках при неудачных запросах.
- **Управление мониторами** — создание, редактирование, включение, отключение и удаление мониторов.
- **Автоматическое обновление Dashboard** — обновление информации без перезагрузки страницы.

## Архитектура

Приложение состоит из Backend, базы данных PostgreSQL и Frontend.

Backend предоставляет REST API и отвечает за управление мониторами, выполнение HTTP-проверок, сохранение результатов и планирование автоматических проверок.

Планировщик мониторинга работает внутри процесса Backend и периодически выполняет проверки активных мониторов.

Frontend взаимодействует с Backend через REST API и отображает текущую информацию о мониторах и историю проверок.

## База данных

Для хранения данных используется PostgreSQL. Основная схема включает две таблицы.

### monitors

Содержит информацию о мониторах и их настройках.

| Поле | Описание |
|---|---|
| `id` | Уникальный идентификатор монитора |
| `name` | Название монитора |
| `url` | URL для мониторинга |
| `interval_seconds` | Интервал проверки в секундах |
| `is_active` | Состояние мониторинга |
| `created_at` | Дата создания |
| `updated_at` | Дата последнего изменения |

### check_results

Содержит результаты выполненных проверок.

| Поле | Описание |
|---|---|
| `id` | Уникальный идентификатор результата |
| `monitor_id` | Идентификатор связанного монитора |
| `status` | Статус проверки (`UP` или `DOWN`) |
| `status_code` | HTTP-код ответа |
| `response_time_ms` | Время ответа в миллисекундах |
| `error_message` | Описание ошибки, если она возникла |
| `checked_at` | Дата и время проверки |

Каждый результат проверки связан с определённым монитором через `monitor_id`. При удалении монитора его история проверок также удаляется.

## REST API

Backend предоставляет следующие REST API endpoints:

| Метод | Endpoint | Описание |
|---|---|---|
| `GET` | `/api/monitors` | Получение списка мониторов |
| `POST` | `/api/monitors` | Создание монитора |
| `GET` | `/api/monitors/{id}` | Получение информации о мониторе |
| `PATCH` | `/api/monitors/{id}` | Изменение настроек монитора |
| `DELETE` | `/api/monitors/{id}` | Удаление монитора |
| `POST` | `/api/monitors/{id}/check` | Ручной запуск проверки |
| `GET` | `/api/monitors/{id}/history` | Получение истории проверок |

## Безопасность

Python Backend включает механизм защиты от SSRF (Server-Side Request Forgery) при обработке пользовательских URL.

Реализованы проверка разрешённых IP-адресов, блокировка непубличных адресов, закрепление IP-адреса для соединения и отключение автоматических перенаправлений.

Поддерживаются только HTTP- и HTTPS-адреса.

## Установка и запуск

### Требования

Для запуска проекта необходимы:

- Python 3.10+
- Docker Desktop
- Git

### 1. Клонирование репозитория

```bash
git clone https://github.com/Zelllar/api-monitor.git
cd api-monitor
```

### 2. Запуск PostgreSQL

Запустите Docker Desktop, затем из корневой папки проекта выполните:

```bash
docker compose up -d postgres
```

Проверить состояние контейнера можно командой:

```bash
docker compose ps
```

PostgreSQL запускается на порту `5432`.

При первой инициализации базы данных Docker автоматически выполняет SQL-скрипт `database/schema.sql`.

### 3. Настройка Python Backend

Перейдите в папку Python backend:

```bash
cd backends/python
```

Создайте виртуальное окружение:

```bash
python -m venv .venv
```

Активируйте его.

Для Windows CMD:

```cmd
.venv\Scripts\activate.bat
```

Для PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Установите зависимости:

```bash
pip install -r requirements.txt
```

Создайте файл `.env` в папке `backends/python`, скопировав шаблон настроек:

```cmd
copy .env.example .env
```

Пароль должен совпадать со значением `POSTGRES_PASSWORD` в `docker-compose.yml`.

Запустите Backend:

```bash
uvicorn app.main:app --reload
```

Backend будет доступен по адресу:

`http://127.0.0.1:8000`

Документация API (Swagger UI):

`http://127.0.0.1:8000/docs`

### 4. Запуск Frontend

Откройте новый терминал в корневой папке проекта и выполните:

```bash
python -m http.server 5500 --bind 127.0.0.1 --directory frontend
```

Frontend будет доступен по адресу:

`http://127.0.0.1:5500`

Также для локальной разработки можно использовать расширение Live Server в Visual Studio Code. В этом случае необходимо использовать адрес `http://127.0.0.1:5500`, поскольку он указан в настройках CORS Backend.

### 5. Запуск тестов

Для запуска автоматизированных тестов Python Backend перейдите в папку `backends/python`, активируйте виртуальное окружение и выполните:

```bash
pytest
```

### Остановка приложения

Для остановки Backend и Frontend используйте `Ctrl + C` в соответствующих терминалах.

Для остановки PostgreSQL выполните из корневой папки проекта:

```bash
docker compose down
```

Данные PostgreSQL сохраняются в Docker volume `postgres_data`.
